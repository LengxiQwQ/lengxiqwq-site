# 聊天室迁移对照审计

2026-11-14。主仓基线 `bc6469f3e3d76b9b80c77cba11dcfd02d3c737ef`，VPS `/opt/chat-server/server.mjs` SHA-256 `4e34cc11c9f03f3259feda14b21a1b892c04642a6243588098d92979b96b31b7`。下文 VPS 源码行号对应这份基线。本次只读检查了生产网关、Caddy 路由和数据结构，在两地临时目录对补丁使用虚构数据和模拟 Matrix 上游进行了回归。

旧版基线的 `chat-worker/src/index.ts` 是 Hono HTTP 入口。聊天室写入路径在 `chat-worker/src/do/room.ts`，消息和转发任务实际落在 Durable Object SQLite（`ctx.storage.sql`），旧仓示例绑定也采用 SQLite DO。这与站点其他 Worker 使用 D1 是两件事。VPS 当前由 Node 进程提供网关服务，Caddy 和 Tuwunel 分别在 Docker 容器运行。VPS 的两个聊天域名在 Caddy 中指向同一网关。

### 补丁范围复核

审计初版 `vps-gateway.patch` 是试验候选，应留作参考。它同时修改了账号注册、缓存、媒体类型、附件 URL、发言频率、消息序号、点歌匹配和多个超时。已找到的回归面包括入房失败后联邦发送静默停止、`m.notice` 等原可显示类型被过滤、拒绝可能合法的 Matrix 媒体重定向、HTTPS-only 与媒体大小限制收窄附件兼容、改房内 ID 影响既有游标。它也无法处理前端断线期间积累的撤回墓碑。隔离测试通过不足以支持一次性上线。

当前优先候选 `scripts/chat-gateway-audit/vps-priority.patch` 只触及生产 `server.mjs` 的历史响应与旧中继前缀。`priority-regression.mjs` 在本地与 VPS 临时目录验证了撤回过滤、回复摘要抹除、房间隔离、外部冒充、旧可信中继以及 `m.notice` 保留。生产源码 SHA-256 与上一轮相同。这轮没有部署补丁、修改数据库或轮换凭据。

## 数据核对

VPS 有 **7 个主 JSON 文件和 2 个 `.bak`**。快照的文件全部能解析。以下数字来自文件；实时冒烟读到互联房 516 条，期间房间仍有新消息，因此两次读数不能当成同一时点的对账。

| 文件 | 结果 |
| --- | --- |
| `messages_chat.json` | 365 条。无重复 UID/ID、无倒序、无撤回记录。 |
| `messages_interconnect.json` | 513 条。无重复 UID/ID/已识别 Matrix ID，相邻 ID 倒序 2 处，撤回 2 条，带独立 `matrixEventId` 7 条。现场分页返回了这 2 条撤回记录。 |
| `members.json` | 10 条，访客 6、Waline 4，重复键 0，Matrix 前缀或 Matrix 类型 0。这是快照结论。 |
| `playlists.json`、`playlist_details.json` | 5 个唯一 ID，详情无缺。曲目数 53、92、301、337、637，共 1420。QQ 歌单 991 首均有匹配，网易云 429 首中 4 首有 QQ 匹配。 |
| `music_history.json`、`music_request_logs.json` | 47 条聚合、50 条请求日志。当前 `current` 与 `queue` 不在这两个文件里。 |

`run-migration.mjs` 的历史来自旧公开 WS 分页，旧接口已过滤撤回；脚本还直接逐文件覆盖，没有共同快照、异常门槛或旧新写入水位。因此无法据现有文件证明 DO 全量导入、离线期间 Matrix 无缺口，或成员/歌单写入没有遗漏。两个别名目前都由同一个 Caddy 后端响应，不能再把 `chat-api` 当成独立的旧系统重跑导出。

## 风险与整改

### 高

1. **生产凭据与权限**。`server.mjs:16–28` 硬编码多个生产密钥，主文件和两个源文件备份权限均为 0644，进程以 root 在用户会话中运行。网关早期审计输出也出现过凭据值。尽快轮换 Matrix 管理令牌、注册令牌、访客签名密钥、音频签名与上游凭据，把配置放入仅服务账户可读的环境文件；检查备份和日志可见范围。分离访客签名、身份派生和 Matrix 账号凭据。先固化现有访客键与 Matrix 账号映射，再切换秘密，避免一轮轮换同时改掉历史归属和确定性密码。移除系统会话方式启动，由非 root 受管服务运行。
2. **联邦身份伪装及回环数据误配**。`1630–1672、1780–1805` 接受外部正文中的本地身份、头像和显示名，冒充可污染消息归属和 UI，甚至令同正文的独立事件被吞。现版本正向鉴权仍来自 WS 会话，文本伪装本身不等于获得管理员令牌。补丁以 sender 定身份，只在可信 sender 对应的本地 UID 上做回环。发布前需盘点旧记录里的外部来源却使用本地键的条目，按原始 Matrix 事件核对后修复；没有原始事件的项单独报告。把站点归属和管理许可统一为精确身份/可信来源字段，避免依徽章、昵称或域名子串授权。
3. **撤回后仍可读取、跨端删除失效**。`1040、1103、1268–1316、1767`。补丁过滤历史和回复摘录，保留删除记录，用 `matrixEventId` 调用 Matrix redaction，并接收入站 redaction。仍需用持久重试任务处理 Matrix 403/429/超时，记录待发送消息上的删除意图，保证重启后继续。迁移来的纯旧 UID 若缺映射，先回填 Matrix 源证据。上线后用两端相同事件 ID 精确核验。
4. **静默丢消息及进程崩溃窗口**。`66–108、1502–1550、1732–1820`。生产每次写入都重置两秒计时，持续流量可一直延期；跨文件没有事务，写失败只记日志，JSON 损坏可能回退为空并覆盖。Sync 提前推进内存游标，重启清空且忽略 limited；发信无持久任务，联邦发送失败后站内已显示成功。候选补丁只缩短磁盘风险和延后当批游标推进。完整整改把消息、成员、事件映射、Sync 检查点、待转发/待撤回、歌单与播放状态写进本地 SQLite；消息与待转发任务同一事务，落盘后确认。采用稳定 owner/device/事务 ID，按 `prev_batch` 补齐 limited timeline，再原子推进 `next_batch`。使用按日备份和恢复演练，记录最后成功持久化和 Sync 延迟。 [Matrix Sync 与历史分页规范](https://spec.matrix.org/latest/client-server-api/#syncing)
5. **媒体代理主动内容与资源耗尽**。`855–885` 用高权限令牌代理任意 MXC、信任 MIME 并公开缓存一周、全缓冲；可以借代理在聊天域名呈现活跃文档，能访问哪些非公开媒体取决于上游权限与媒体 ID，尚未实证。补丁限制位图、体积、超时及响应头，拒绝重定向。完整版本用发布过的媒体引用授权，换独立权限账号、隔离媒体域，独立并发上限与缓存撤销。
6. **匿名可干预共享点歌，网关边界偏宽**。`1216–1265` 允许匿名入队，任何观察者掌握公开播放 UID 即可立即发 ended；生产没有旧版播放已达尾段守卫。候选恢复认证和时间门槛，仍需统一最短/最长时长、投票统计、状态锁、单用户配额，防止并发 fallback 覆盖新点歌。HTTP/WS 增加 Origin allowlist、每 IP/账号/连接额度、POST 体积限制和超时。当前 Node 监听所有接口，外网单点探测超时；结合 Caddy 的容器网段限制 3001 并保留外部端口验证。URL 携带 Waline/访客 Token，建议改为 WS 首包鉴权或短期一次性票据并配置日志脱敏。

### 中

- **歌单管理和点播完整性**。按旧路由契约恢复 `import/refresh/flags/delete`、归属权限、分页、详情缓存和 `playlist:updated`。精选/个人状态由已认证成员与房间上下文计算，刷新来源时保留现有匹配。不可靠的跨平台搜索匹配保持未匹配。只有业务确认需要原生网易云后引入对应 Provider。队列临播时重新解析短期流签名，音频 Range 改流式响应。统一 `room:register_fallback` 的候补曲目和本地音源 allowlist。
- **联邦消息兼容**。短码以清单定位，贴纸/图片考虑回到旧桥的上传 `m.image`。文本由安全的 Markdown AST 生产 Matrix 允许的 HTML 和可读纯文本；入站仅从受限结构映射图片与链接。用 `m.relates_to` 映射回复，`m.mentions` 映射提及，明确处理 `m.replace` 和不支持的加密事件。对限流、重发、远程客户端屏蔽外链做验收。 [Matrix 消息类型](https://spec.matrix.org/latest/client-server-api/#mroommessage)
- **账户、Profile 与资料一致性**。按已登录帐号归并历史 guest，站内首次 Waline WebSocket 补成员登记；同步同身份多端资料和徽章，清理被误写的徽章及 URL。Guest 邮箱无所有权证明，同邮箱可重签同一身份；需要一次性验证或独立匿名 ID。Matrix 账号用稳定映射和可恢复的设备凭据，加注册全局并发额度，区分临时失败与不存在，失效时刷新。Matrix member cache 记录 membership、状态来源与有效期；本地账号的站外资料身份从映射得出。
- **存在状态与规模**。`clients` close 前泄漏和半开已打补丁。远端活跃从“最近发言”单独展示，刷新到期广播和全局计数，票数基于同口径有效用户。`userMatrixTokenCache` 补丁有上界，`matrixProfileCache`、消息、播放日志、投票集合等仍需要存储索引、合理容量或归档。硬盘日志切片无法约束运行时日志。生产没有 `recentlySentMsgTexts`；无 TTL 的旧去重兜底分支才是已发现的 `recentlySentEventIds` 增长来源。
- **历史和重连**。修补按新序号划分的缺口，重连用最后收到的游标补齐，即使超出 50 条也不丢。服务端保存按用户与房间区分的读游标，分页需处理迁移前重复 ID 和失序。前端按 UID 去重，收到墓碑或版本变更后失效旧缓存；当前内存缓存可能把重连时已删除的旧内容带回。鉴权未完成的 WS 早到包需排队或由就绪握手发指令。
- **公开数据及运维**。`/api/members` 直接返回原始成员对象，应用明确的公开投影；修改头像/主页约束 URL。读取历史时过滤逻辑删除，统计也遵从房间、来源及可见性契约。加健康检查分项、反向代理限流、备份一致性与告警，固定容器镜像版本。

### 低

- 切房时 `room:init` 原先将在线数写死为 1，补丁改用房间统计；仍应整理 `room:init` 与 `presence:update` 的字段契约。
- 站长 Matrix 身份映射写死为 `waline:1`，不应通用依赖账号序号。菱形昵称后缀拆分会改写用户真实昵称，应与发信网关附加的标签分开。
- 播放状态每个事件序列化整份历史与队列发送给所有连接。优先测量房间规模和推送大小，再按实际流量决定是否拆为带版本的增量事件。
